# buzz

[Buzz](https://github.com/block/buzz) relay, deployed following
[Run your own Buzz relay](https://engineering.block.xyz/blog/run-your-own-buzz-relay).

| Piece        | Where                                                        |
| ------------ | ------------------------------------------------------------ |
| Relay        | `ghcr.io/block/buzz:v0.5.2`, served on `https://buzz.$domain` |
| Database     | CloudNativePG cluster `main`, database and role `buzz`        |
| Redis        | shared `valkey.valkey`                                       |
| Media store  | MinIO in this namespace, bucket `buzz-media`                  |
| Git repo     | PVC `buzz/data` mounted at `/data/git`                        |

The relay is closed membership (`BUZZ_REQUIRE_RELAY_MEMBERSHIP=true`): only the
owner and explicitly added members can publish.

## Setup

The relay needs its Nostr identity keys, which cannot be committed. `secret.yaml`
is therefore not tracked: copy the example, fill it in, encrypt it, then add it to
`kustomization.yaml`.

```bash
cd 030-software/fluxcd/apps/buzz
cp secret.example.yaml secret.yaml

# relay identity: keep this private key forever, it is the relay identity
docker run --rm --entrypoint /usr/local/bin/buzz-admin ghcr.io/block/buzz:v0.5.2 generate-key

# owner pubkey is the public key of the nostr account that owns this relay
# minio credentials, shared between minio and the relay
openssl rand -hex 32   # BUZZ_GIT_HOOK_HMAC_SECRET
openssl rand -hex 16   # BUZZ_S3_ACCESS_KEY
openssl rand -hex 32   # BUZZ_S3_SECRET_KEY

# database password, generated by CloudNativePG for the buzz role
kubectl get secret buzz -n cnpg-system -o jsonpath='{.data.password}' | base64 -d

# fill secret.yaml, then
sops --encrypt --in-place secret.yaml
# and add `- secret.yaml` to resources in kustomization.yaml
```

Until that secret exists, the relay and MinIO stay in `CreateContainerConfigError`.

## Membership

The owner account can add members from the relay pod:

```bash
kubectl -n buzz exec deploy/buzz -- /usr/local/bin/buzz-admin add-member <pubkey>
kubectl -n buzz exec deploy/buzz -- /usr/local/bin/buzz-admin list-members
```

## Backups

`BUZZ_RELAY_PRIVATE_KEY`, the `buzz` database, the `buzz-minio` PVC (`buzz-media`
bucket) and the `buzz` PVC (`/data/git`). Losing the relay key means adopting the
old key as owner, or starting over with a new relay identity.

## Upgrades

Bump the image tag in `deployment.yaml` to a
[release](https://github.com/block/buzz/releases) and let Flux roll it.
`BUZZ_AUTO_MIGRATE=true` runs the schema migrations on start.
